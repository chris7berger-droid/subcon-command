# Sales Command Security Audit — 2026-09-21

## Summary

0 Critical, 22 High, 12 Medium, 13 Low — posture **regressed on new client-side surfaces (Schedule shell, HistoryLocker, BillingScheduleSection, ArchiveProposalModal) and adds one NEW HIGH CSRF on the QuickBooks OAuth callback**. Prior fixes landed cleanly on `Settings.handleSave` (D3 → CLOSED), `qb-record-payment` service-role hard-block (C16 → CLOSED), and `reset-password` undeclared `origin` (C-reset-password → CLOSED, replaced with hardcoded `https://www.scmybiz.com`). However, the surface expanded significantly since 2026-08-03 — the AR Command driver landed in-tree (`src/ar/*`), Field driver landed (`src/field/*`), and a large Schedule driver refactor shipped many new components — none with proper role gates on their write handlers. The `stripe-webhook → qb-record-payment` retention bug remains (C-qb-record-payment-net at :167, moved from :153). All prior D-series client-only gate holes remain open at their new line numbers. Fifth audit cycle for `A4` (magic link log), `C-reset-password-listusers`, `F-PayAppDetailModal-cascade`.

## Top 3 Urgent

1. **NEW HIGH — QBCallbackPage no OAuth state validation (CSRF).** `src/pages/QBCallbackPage.jsx:34` accepts `code` + `realmId` straight from the URL and forwards them to the `qb-auth` exchange fn with no state parameter check. The auth-start URL in `Invoices.jsx:3219` / `Settings.jsx:417` sends a hardcoded literal `state=salescommand`, so no per-session nonce is stored. An attacker who tricks any authenticated Admin/Manager into clicking a crafted `/qb/callback?code=…&realmId=…` link swaps the victim tenant's QuickBooks linkage to the attacker's realm, pivoting all future SC→QB invoice syncs into the wrong company file. Classic RFC 6749 §10.12 CSRF against an OAuth callback. Fix: mint a random state at auth-start, store in sessionStorage, reject callback when returned `state` doesn't match.

2. **NEW HIGH — Schedule shell + HistoryLocker + BillingScheduleSection + ArchiveProposalModal ship 5 new client-side money-write / destructive surfaces with no role gate.** `src/schedule/ScheduleLayout.jsx:222,236,244,253,263,271,287,305` writes crew/work_types/assignments/crew_status directly (any authed user can delete a crew and cascade-wipe their assignments). `src/components/HistoryLocker/ArchiveBatchManager.jsx:21` cascade-deletes archived legacy_records via `archive.import_batches` DELETE with no role check. `src/components/BillingScheduleSection.jsx:102,121,142,160,169,203` defines `canManage` at :19 but only uses it to hide/show buttons — every write handler (createSchedule, saveDraftAsLine, saveLineEdit, deleteLine, updateRetainage, lockSchedule) skips the gate at handler entry. `src/components/ArchiveProposalModal.jsx:97` mints a Sold proposal with client-supplied `total: amount` and no role check. Combined with the still-open D-WTCCalculator / D-MobilizationsEditor / D-ProposalDetail-batch / D-ArchiveProposalPanel handlers, any Sales Rep can rewrite money / mint jobs / destroy archive history at will. Fix: role-check at every handler entry; back with RLS UPDATE/DELETE/INSERT policies on the affected tables.

3. **B-PublicInvoicePage-wide-select (HIGH — fourth cycle) — DB-level anon SELECT grant on `proposal_wtc` still ships cost basis.** `src/pages/PublicInvoicePage.jsx:60` now carries a self-authored comment (added 2026-08-10 by security review): *"proposal_wtc carries a TABLE-level anon SELECT grant, so a link holder can query burden_rate / markup_pct / pw_rate / materials / discount straight from PostgREST regardless of what this page selects."* The client-side allow-list is defensive but is NOT the security boundary. An anon caller with a valid `viewing_token` can `GET /rest/v1/proposal_wtc?select=*` and read burden_rate, ot_burden_rate, pw_rate, pw_ot_rate, markup_pct, materials jsonb, discount for every proposal referenced by a live invoice. `PublicSigningPage` was migrated to a SECURITY DEFINER RPC (H6/2026-05-02); the invoice page was never migrated. Backlog S13 is the tracked fix. Fix: mirror the H6 pattern — `get_public_invoice_view(p_token uuid)` RPC returning only invoice header + safe per-line fields; `REVOKE SELECT ON public.proposal_wtc FROM anon;` in `command-suite-db`.
