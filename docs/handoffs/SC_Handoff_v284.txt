CANONICAL VISUAL PRINCIPLE
Photography creates environment. Functionality determines layout.
Warm construction/material environment + espresso/graphite translucent command
surfaces + warm high-opacity operational surfaces + cyan command instrumentation
+ disciplined industrial typography + semantic operational colors.
Professional equipment, not decoration. Cyan is the command accent, not teal.
Preserve green healthy/available/completed, amber/orange attention/risk, red
intervention/missing/blocked, purple/blue assignment/category, gray neutral/
unavailable meanings. Use existing fonts: Barlow Condensed for command/heading
and KPI emphasis, Inter for UI/data, existing appropriate JetBrains Mono usage;
readability and stable layout take priority over forcing font changes.

PHOTOGRAPHY / SURFACE RULE
Construction photography belongs to PAGE / ENVIRONMENT, not inside individual
operational components. Full-bleed construction environment may sit behind app
content; command/cinematic modules and small mounting gaps reveal it through
controlled dark translucency. Dense surfaces suppress recognizable imagery.
Schedules, tables, job rows, forms, editors, filters and text-heavy operational
data use high-opacity warm sand/ivory technical paper. Subtle linen/material
character is allowed; recognizable photographic bleed-through is not.
Worker/hard hat may be partly or heavily obscured. No decorative photo height
at the expense of real controls, density or operational screen space.

STRUCTURE / FUNCTION SOURCE OF TRUTH
The existing REAL application is always authoritative: component structure,
information architecture, controls, labels, ordering, values, calculations,
data bindings, permissions, routes, navigation, interactions, responsive,
scrolling/sticky behavior and dialogs/dropdowns. Mockups are visual/material
references only; do not infer new functionality or changed information,
controls, calculations, data or interactions from an AI-generated mockup.
Do not recreate mockups as replacement JSX. Reskin the existing functioning
application. Prefer scoped CSS, reuse DOM, avoid unintended shared-screen
changes. If structural/functional changes are required, stop on that item and
seek separate approval. No global theme rollout implied by this preview.
