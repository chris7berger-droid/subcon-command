CHANGES (code = e508736)

  marker rule, startup rule, reset flow bound to the verified auth user id.
src/App.jsx — holds session-bearing auth events during a reset; never applies
  a hashless PASSWORD_RECOVERY; on startup ends an unfinished recovery session
  instead of admitting it; "Remember me"-off startup sign-out skips a tab
  opened by a recovery link; applies a confirmed password sign-in.
src/pages/Login.jsx — one mounted form through verify -> save -> sign-out;
  rejected save retries without re-verifying; sign-out result checked; link
  mode (no code field); Back / Request a new code end the recovery session;
  no longer strips a token-bearing URL hash before the auth client reads it.
src/lib/passwordRecovery.test.mjs, scripts/check-password-recovery.mjs (new).
No dependency, migration, edge function, mail, Supabase setting or native
change.

DECISIONS
- Hold the App's state rather than move/remount Login mid-submit.
- Marker localStorage sc_recovery_user = verified user id while a reset is
  unfinished. Never a code or password. Cleared only after a confirmed
  sign-out or a successful password sign-in.
- Refresh/return during an unfinished reset ENDS the recovery session (new
  code needed) rather than resuming it.
- Link recovery was broken on origin/main too; fixed because links were in
  scope.
